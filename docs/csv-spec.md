# CSV の項目定義（データ定義書）

レジ（`/admin`）と管理画面（`/master`）からダウンロードできる売上の CSV の仕様です。
デジタル庁「[機械判読可能なデータの表記方法の統一ルール](https://github.com/digital-go-jp/machine_readability_rule)」に沿って作っています。

> Excel で開いて人が集計するときは、手集計用の `sales_ja.csv`（[csv-tally-spec.md](csv-tally-spec.md)）が便利です。このページの 3 ファイルは、プログラムでの分析・ほかのデータとの結合に向けた形式です。

## ファイルの一覧

| ファイル | URL | 1 行の単位 | 主な用途 |
|---|---|---|---|
| 会計 | `/api/admin/sales.csv` | 1 回の会計 | 売上・支払方法・時間帯の集計 |
| 明細 | `/api/admin/sale_items.csv` | 1 回の会計 × 1 商品 × 1 味 | 商品ごと・味ごとの本数の集計 |
| セットの内訳 | `/api/admin/sale_packs.csv` | 1 回の会計 × 1 商品 × 1 セットの種類 | セットごとの個数、商品ごとの金額 |

- 管理画面からは `/api/master/` で始まる同じ名前の URL で取得できます（内容は同じ）。
- どれもログインが必要です（レジ用または管理画面のログイン）。
- 3 つのファイルは `sale_id`（会計番号）でつながります。`sale_items.csv` と `sale_packs.csv` の `sale_id` は、`sales.csv` の `sale_id` を参照します。
- ファイル名は `mogiten_<種類>_<作成日時 YYYYMMDDHHMM（日本時間）>.csv` です（例: `mogiten_sales_202611021930.csv`）。

## 共通の形式

| 項目 | 内容 |
|---|---|
| 形式 | CSV（RFC 4180 準拠）。区切り文字はカンマ `,` |
| 文字コード | UTF-8。既定で先頭に BOM（`EF BB BF`）を付ける（Windows の Excel で文字化けしないため）。URL の末尾に `?bom=0` を付けると BOM なしで出力 |
| 改行 | CRLF（`\r\n`）。最後の行の後にも改行あり |
| 1 行目 | 項目名（英小文字・数字・`_` の物理名）。2 行目からデータ。タイトル行・空行・注記はない |
| 囲み | 値にカンマ・ダブルクォート・改行を含むときだけダブルクォート `"` で囲み、中の `"` は `""` にする |
| 1 行 1 データ | 値の中に改行は入らない（商品名・味・担当者名は入力時に改行などの制御文字を取り除いている） |
| 金額 | 円の整数。桁区切りのカンマ・`¥`・`円` は付けない。単位は項目名の末尾 `_yen` で示す |
| 数量 | 整数。単位（本・個など）は `unit_name` の列に別に持つ |
| 日時 | ISO 8601、日本時間（例: `2026-11-02T11:48:26+09:00`） |
| 日付 | `YYYY-MM-DD`（日本時間の営業日。例: `2026-11-02`） |
| 空欄 | 「値がない」（該当しない・まだ起きていない）を表す。**ゼロとは区別する**。ゼロのときは `0` と書く |
| 取消 | レジで取り消した会計は 3 つとも含めない（データベースには取消の印つきで残っている） |
| 並び順 | `sale_id` の昇順 |
| 作成時点 | ダウンロードした時点の記録。オフラインのレジにある未送信の会計は、送信されるまで含まれない |
| 数式対策 | 文字列の値が `=` `+` `-` `@` で始まるときは、Excel が数式として実行しないよう先頭に `'` を付ける（商品名・味・担当者名だけが対象。数値には付けない） |

## sales.csv（会計）

1 行 = 1 回の会計。

| 物理名 | 論理名 | 型 | 単位 | 空欄 | 説明 |
|---|---|---|---|---|---|
| `sale_id` | 会計番号 | 整数 | — | なし | 会計ごとの番号（1 から順に増える）。キッチン画面・レジの「#」と同じ。全リセットすると 1 に戻る |
| `sold_at` | 会計日時 | 日時 | — | なし | レジの端末で会計した日時（オフラインで記録した会計も、端末で会計した時刻） |
| `business_date` | 営業日 | 日付 | — | なし | `sold_at` の日本時間の日付 |
| `payment_method` | 支払方法 | 文字列（コード） | — | なし | 下の「支払方法のコード表」の値のどれか |
| `item_quantity` | 販売数 | 整数 | 商品の単位（本など） | なし | この会計の商品の数の合計（すべての商品を足した数） |
| `goods_amount_yen` | 商品代 | 整数 | 円 | なし | セットを組んだあとの商品の代金（容器代を除く） |
| `container_fee_charged_yen` | 容器代（受け取った額） | 整数 | 円 | なし | 実際に受け取った容器代（レジで手動で直した場合はその値） |
| `container_fee_auto_yen` | 容器代（自動計算） | 整数 | 円 | なし | ルールで自動計算した容器代。`container_fee_charged_yen` と違えば手動で直した会計 |
| `total_amount_yen` | 合計金額 | 整数 | 円 | なし | お客さんから受け取った金額。`goods_amount_yen + container_fee_charged_yen` |
| `staff_name` | 担当者名 | 文字列 | — | まれに空 | レジにログインしていた担当者の名前（最大 30 文字） |
| `kitchen_done_at` | 調理完了日時 | 日時 | — | あり | キッチン画面で「できた」にした日時。**空欄 = まだ「できた」になっていない**（またはキッチン画面を使っていない） |

### 支払方法のコード表（`payment_method`）

| 値 | 意味 |
|---|---|
| `現金` | 現金 |
| `PayPay` | PayPay（QR コード決済） |
| `d払い` | d払い（QR コード決済） |

表記はこの 3 つに固定されていて、表記の揺れはありません。

## sale_items.csv（明細：商品・味ごと）

1 行 = 1 回の会計 × 1 つの商品 × 1 つの味（縦持ち）。
味ごとの本数を数えるときに使います（例: `flavor` が `みたらし` の行の `quantity` を足すと、みたらしの販売本数）。

| 物理名 | 論理名 | 型 | 単位 | 空欄 | 説明 |
|---|---|---|---|---|---|
| `sale_id` | 会計番号 | 整数 | — | なし | `sales.csv` の `sale_id` |
| `sold_at` | 会計日時 | 日時 | — | なし | `sales.csv` と同じ（集計しやすいように重ねて持つ） |
| `business_date` | 営業日 | 日付 | — | なし | `sales.csv` と同じ |
| `product_id` | 商品 ID | 整数 | — | まれに空 | 管理画面の商品の ID。商品名を変えても同じ ID。商品管理を入れる前の古い記録では空 |
| `product_name` | 商品名 | 文字列 | — | なし | 会計した時点の商品名 |
| `flavor` | 味 | 文字列 | — | あり | 会計した時点の味の名前。**空欄 = 味を選ばない商品**（焼きマシュマロなど）、または味の記録がない古い会計 |
| `quantity` | 数量 | 整数 | `unit_name` | なし | その商品のその味の数（1 以上） |
| `unit_name` | 単位 | 文字列 | — | なし | 数量の単位（例: `本`） |

- 1 回の会計の `quantity` を全部足すと、`sales.csv` の `item_quantity` と一致します。
- 金額はこのファイルにはありません（セットは味をまたいで組むため、味ごとの金額は決まらない）。金額は `sales.csv` または `sale_packs.csv` を使います。

## sale_packs.csv（セットの内訳）

1 行 = 1 回の会計 × 1 つの商品 × 1 つのセットの種類。
レジは本数からお客さんに一番有利なセットを自動で組むので、その組み方を記録したものです。

| 物理名 | 論理名 | 型 | 単位 | 空欄 | 説明 |
|---|---|---|---|---|---|
| `sale_id` | 会計番号 | 整数 | — | なし | `sales.csv` の `sale_id` |
| `sold_at` | 会計日時 | 日時 | — | なし | `sales.csv` と同じ |
| `business_date` | 営業日 | 日付 | — | なし | `sales.csv` と同じ |
| `product_id` | 商品 ID | 整数 | — | まれに空 | `sale_items.csv` と同じ |
| `product_name` | 商品名 | 文字列 | — | なし | 会計した時点の商品名 |
| `pack_size` | セットの数量 | 整数 | `unit_name` | なし | 1 セットに入る数（例: 5 本セットなら `5`、単品なら `1`）。ほかの商品と混ぜたセットでは「この商品の数」 |
| `pack_price_yen` | セットの価格 | 整数 | 円 | なし | 1 セットの価格（会計した時点）。ほかの商品と混ぜたセットでは、セットの価格をこの商品の数の割合で分けた金額 |
| `pack_count` | セットの個数 | 整数 | 個 | なし | そのセットをいくつ売ったか。混ぜたセットの行は常に `1` |
| `amount_yen` | 金額 | 整数 | 円 | なし | `pack_price_yen × pack_count` |
| `unit_name` | 単位 | 文字列 | — | なし | 数量の単位（例: `本`） |
| `is_mixed_pack` | 混ぜたセットか | 整数（0/1） | — | なし | `1` = ほかの商品と合わせて組んだセット（例: 団子 3 本＋焼きマシュマロ 2 本で 5 本セット）、`0` = その商品だけのセット |
| `mixed_pack_label` | 混ぜたセットの組み方 | 文字列 | — | あり | 混ぜたセットの組み方の説明（例: `5本セット×1`）。同じ会計で同じ値の行が 1 つの混ぜたセット。**空欄 = 混ぜたセットではない**（`is_mixed_pack` が `0`） |

- 1 回の会計の `amount_yen` を全部足すと、`sales.csv` の `goods_amount_yen` と一致します。
- 商品ごとの売上金額は、`product_id` ごとに `amount_yen` を足します。

## 集計の例

| 知りたいこと | 使うファイルと方法 |
|---|---|
| 売上の合計 | `sales.csv` の `total_amount_yen` を合計 |
| 支払方法ごとの売上 | `sales.csv` を `payment_method` でまとめて `total_amount_yen` を合計 |
| 1 時間ごとの売上 | `sales.csv` の `sold_at` の時（`T` の後ろ 2 桁）でまとめる |
| 味ごとの販売本数 | `sale_items.csv` を `product_name` と `flavor` でまとめて `quantity` を合計 |
| 5 本セットが何個売れたか | `sale_packs.csv` で `pack_size` が `5` かつ `is_mixed_pack` が `0` の行の `pack_count` を合計（混ぜたセットは `mixed_pack_label` で数える） |
| 調理にかかった時間 | `sales.csv` の `kitchen_done_at - sold_at`（`kitchen_done_at` が空欄の行は除く） |

Python（pandas）で読む例:

```python
import pandas as pd
sales = pd.read_csv('mogiten_sales_202611021930.csv', encoding='utf-8-sig', parse_dates=['sold_at', 'kitchen_done_at'])
items = pd.read_csv('mogiten_sale_items_202611021930.csv', encoding='utf-8-sig', keep_default_na=True)
items.groupby(['product_name', 'flavor'])['quantity'].sum()
```

## 変更履歴

| 日付 | 内容 |
|---|---|
| 2026-11-02 | `container_fee_yen` を `container_fee_charged_yen`（受け取った容器代）に名前を変更。手集計用の `sales_ja.csv` を追加 |
| 2026-11-02 | 機械判読しやすい形式に変更。それまでの 1 ファイル（日本語の項目名、商品ごとの数量の列が商品の数だけ並ぶ横持ち、「内容」「味」の列に複数の値を「・」でつないで入れる形式、日時はタイムゾーンなし）を、項目名が英数字の 3 ファイル（会計・明細・セットの内訳）に分けた。日時を ISO 8601（+09:00）に、金額の項目名に単位 `_yen` を付けた。調理完了日時（`kitchen_done_at`）と営業日（`business_date`）を追加 |

## 統一ルールとの対応

| ルール | 対応 |
|---|---|
| L1-01 機械が読める形式 | CSV |
| L1-02 1 ファイル 1 表 | 会計・明細・セットの内訳を別ファイルに分けた |
| L1-03／L1-04／L3-01 | 1 行目が項目名、2 行目からデータ。空行・タイトル・注記なし |
| L1-05／L2-03 | すべての列に一意の項目名（この定義書で意味を説明） |
| L1-06／L1-14 | 体裁のための空白・改行なし。値の中に改行なし |
| L1-07 1 セル 1 データ | 「団子4本・焼きマシュマロ1本」「みたらし3・あんこ1」のように 1 つのセルに複数の値を入れていた列をやめ、明細ファイルで 1 行 1 値に |
| L1-09 空白とゼロの区別 | 空欄は「値がない」、ゼロは `0`。空欄になる列と意味をこの定義書に明記 |
| L1-15 | カンマを含む値はダブルクォートで囲む |
| L2-01 数値に文字を混ぜない | 金額・数量は整数だけ。単位は項目名（`_yen`）または `unit_name` 列 |
| L2-02 省略しない | 明細の行にも `sale_id`・日時・商品名を毎行入れる |
| L2-04／L3-02 選択肢の標準化・コード表 | `payment_method` は 3 つの値に固定し、コード表を掲載。`is_mixed_pack` は 0/1 |
| L3-04 単位 | 金額は `_yen`、数量は `unit_name` |
| L3-05 時間軸の標準化 | ISO 8601（西暦・+09:00） |
| L3-08 定義・文字コード | この定義書。物理名は英数字、文字コードは UTF-8（BOM の有無を選べる） |
| L3-09 縦持ち | 商品ごと・味ごとの数を列に並べず、明細ファイルの行にした（商品や味が増えても列は変わらない） |
