# 手集計用 CSV（sales_ja.csv）要件定義・項目定義

Excel で開いて、人が目で見ながら集計するための CSV です。
プログラムでの処理や、ほかのデータとの結合には、機械判読用の 3 ファイル（[csv-spec.md](csv-spec.md)）を使ってください。

## 1. 目的

模擬店の会計係・責任者が、営業後に Excel で売上を確認・集計できるようにする。
特に次の作業を、関数や加工なしで（列の合計・フィルター・ピボットテーブルだけで）できるようにする。

- 売上の合計、支払方法ごとの売上（現金の締め・PayPay と d払いの入金との突き合わせ）
- 味ごとの販売本数（翌年の仕入れ・仕込みの見積もり）
- 担当者ごと・時間帯ごとの会計件数
- 容器代を手で直した会計の確認（容器の準備数の見直し）

## 2. 利用者と利用場面

| 利用者 | 場面 | 使い方 |
|---|---|---|
| 会計係 | 営業終了後のレジ締め | 支払方法でフィルターし、合計（円）の列を合計して現金・PayPay・d払いと照合する |
| 責任者 | 打ち上げ・翌年の準備 | 味ごとの列の合計を見る。会計番号でキッチンの記録と照合する |
| 部員全般 | 振り返り | 1 行ずつ「内容（参考）」を読んで会計を確認する |

## 3. 要件

### 3.1 機能要件

| 番号 | 要件 |
|---|---|
| F-1 | 1 行 = 1 回の会計。取り消した会計は含めない（機械判読用と同じ） |
| F-2 | 1 行目に日本語の項目名、2 行目からデータ。タイトル行・合計行・空行は入れない（並べ替えやフィルター、ピボットテーブルを壊さないため。合計は Excel の SUM で出す） |
| F-3 | 商品ごと・味ごとの本数を **1 つの列に 1 つの味** で並べる（列の合計 = その味の販売本数）。味を登録した商品は、味ごとの列のあとに「計」の列を置く |
| F-4 | 味の列の並びは、管理画面で登録した商品の並び順・味の並び順に従う。いまは売っていない商品や、名前を変えた・消した味でも、記録に残っていれば列を作る（列は右に追加） |
| F-5 | 味を登録した商品で味の記録がない会計（味の機能を入れる前の会計など）は、「（商品名） 味の指定なし」の列に数える。この列は該当する会計があるときだけ作る |
| F-6 | 数量・金額は数値だけを入れ、単位は項目名に括弧で書く（例: `合計(円)`、`団子 みたらし(本)`）。桁区切りのカンマや `¥` は付けない（Excel で計算できるように） |
| F-7 | 本数が 0 の欄は空欄にせず `0` と書く（列の合計・平均が正しく出るように） |
| F-8 | 日付と時刻を別の列にする（日付でフィルター、時刻で時間帯の集計がしやすいように）。日付は `2026/11/02`、時刻は `11:48:26`（日本時間）。Excel が日付・時刻として認識する形 |
| F-9 | 容器代を手で直したかどうかを「あり」「なし」の文字で示す（空欄で表さない） |
| F-10 | 会計の内容を 1 つの文で読める「内容（参考）」の列を最後に置く（例: `団子4本（3本セット×1＋1本×1）〔みたらし2・あんこ1・きなこ1〕`）。集計には使わない参考の列 |
| F-11 | 会計番号はキッチン画面・レジの「#」と同じ番号にする |

### 3.2 非機能要件

| 番号 | 要件 |
|---|---|
| N-1 | Windows・Mac の Excel でダブルクリックして開いたときに文字化けしない（UTF-8・BOM 付き） |
| N-2 | 値にカンマ・ダブルクォート・改行を含むときはダブルクォートで囲む（RFC 4180） |
| N-3 | 文字列が `=` `+` `-` `@` で始まるときは先頭に `'` を付け、Excel の数式として実行されないようにする |
| N-4 | ログインした人（レジ・管理画面）だけがダウンロードできる |
| N-5 | 機械判読用の 3 ファイルと同じ時点の同じ記録から作り、金額・本数が一致する（どちらで集計しても同じ結果） |

### 3.3 機械判読用 CSV との違い（意図して変えている点）

手集計用は「人が Excel で扱う」ことを優先し、デジタル庁の統一ルールのうち次の点を意図して変えています。プログラムで扱うときは機械判読用を使ってください。

| ルール | 手集計用での扱い | 理由 |
|---|---|---|
| L3-08 物理名は英数字 | 項目名は日本語 | Excel を開いた人がそのまま読めるように |
| L3-09 縦持ち | 味ごとの本数を列に並べる（横持ち） | 列を合計するだけで味ごとの本数が出るように。味が増えると列が増える |
| L1-07 1 セル 1 データ | 「内容（参考）」の列だけ、複数の値を 1 つの文にまとめる | 1 行を読むだけで会計の中身がわかるように。集計には使わない列として最後に置く |
| L3-05 時間軸 | 日付 `2026/11/02` と時刻 `11:48:26` を別の列に（タイムゾーンは書かない。すべて日本時間） | Excel が日付・時刻として認識し、フィルターや時間帯の集計ができるように |

そのほかのルール（1 行目が項目名、空行や注記なし、数値に単位を混ぜない、ゼロと空欄の区別、選択肢の表記の統一など）は守っています。

## 4. 項目定義

列は左から次の順に並びます。「商品・味の列」は、そのときの商品と味によって数が変わります。

| 項目名 | 内容 | 例 | 空欄 |
|---|---|---|---|
| `会計番号` | 会計ごとの番号。キッチン画面・レジの「#」と同じ | `12` | なし |
| `日付` | 会計した日（日本時間） | `2026/11/02` | なし |
| `時刻` | 会計した時刻（日本時間） | `11:48:26` | なし |
| `支払方法` | `現金`・`PayPay`・`d払い` のどれか | `現金` | なし |
| `担当者` | レジにログインしていた担当者の名前 | `学祭太郎` | まれに空 |
| **商品・味の列** | | | |
| `（商品名） （味）(単位)` | 味を登録した商品の、その味の本数 | `団子 みたらし(本)` → `2` | なし（0 本は `0`） |
| `（商品名） 味の指定なし(単位)` | 味を登録した商品で、味の記録がない本数（該当する会計があるときだけ） | `団子 味の指定なし(本)` | なし |
| `（商品名） 計(単位)` | 味を登録した商品の、味をすべて足した本数 | `団子 計(本)` → `4` | なし |
| `（商品名）(単位)` | 味のない商品の本数 | `焼きマシュマロ(本)` → `1` | なし |
| **金額などの列** | | | |
| `販売数(本)` | この会計の商品の本数の合計（単位が商品によって違うときは `販売数(点)`） | `5` | なし |
| `商品代(円)` | セットを組んだあとの商品の代金（容器代を除く） | `500` | なし |
| `容器代(円)` | 実際に受け取った容器代 | `10` | なし |
| `容器代の自動計算(円)` | ルールで自動計算した容器代 | `10` | なし |
| `容器代の手直し` | 容器代をレジで手で直したか。`あり`（`容器代(円)` と自動計算が違う）または `なし` | `なし` | なし |
| `合計(円)` | お客さんから受け取った金額（`商品代(円)` ＋ `容器代(円)`） | `510` | なし |
| `キッチンでできた時刻` | キッチン画面で「できた」にした時刻（日本時間） | `11:55:02` | あり（まだ「できた」でない、またはキッチン画面を使っていない） |
| `内容（参考）` | 会計の内容を 1 つの文にしたもの（集計には使わない） | `団子4本（3本セット×1＋1本×1）〔みたらし2・あんこ1・きなこ1〕` | なし |

## 5. 集計のしかた（Excel）

| 知りたいこと | 操作 |
|---|---|
| 売上の合計 | `合計(円)` の列を選ぶ（右下のステータスバーに合計が出る）か、`=SUM(…)` |
| 現金の売上（レジ締め） | 見出しの行で「フィルター」→ `支払方法` で `現金` だけにして `合計(円)` を選ぶ |
| みたらしが何本売れたか | `団子 みたらし(本)` の列を選んで合計を見る |
| 時間帯ごとの売上 | 「挿入」→「ピボットテーブル」で、行に `時刻`（時間でグループ化）、値に `合計(円)` |
| 担当者ごとの会計件数 | ピボットテーブルで、行に `担当者`、値に `会計番号` の個数 |
| 容器代を手で直した会計 | `容器代の手直し` を `あり` でフィルター |
